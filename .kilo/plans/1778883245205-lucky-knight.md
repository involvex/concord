## 4 · Architecture — what every new file should know

### Command / event loop pattern

The app is driven by a **command queue** (`tokio::sync::mpsc::Sender<AppCommand>`)
and an **effect stream** (`tokio::sync::mpsc::Receiver<SequencedAppEvent>`).

- `app.rs::start_command_loop` — receives commands, calls Discord REST, publishes
  `AppEvent` effects back into the stream.
- `tui/runtime.rs::run_dashboard` — the top-level `tokio::select!` loop that:
  - Drains terminal events → `events::handle_terminal_event` → mutates state / sends commands
  - Drains image-decode results → updates `ImagePreviewCache`
  - Drains snapshot changes → `state.restore_discord_snapshot` + deferred effects
  - Drains sequenced effects → `effects::process_sequenced_effect`
  - Background timers: redraw debounce (80 ms), read-ack flush, toast expiry
  - Auto-sends: history, pinned-messages, forum posts, member subscriptions, profiles, thread previews, member-list subscription ranges

### Key structural decisions

- `src/app.rs` owns both the command sender and the effect receiver state and orchestrates them in a controlled concurrency with no `Send + Sync` constraints.
- `vecdeque` is used for in-memory command staleness caches to ensure TUI commands flow back to the command queue.
- `src/tui/state/image_viewer.rs` — image viewer model methods only on `DashboardState`
- Image preview cache (`ImagePreviewCache`) enforces a hard cap of 16 entries; LRU eviction trims unprotected entries by `last_used` tick.
- Member subscription: when a member list scrolls into a new 100-member bucket, it sends an `UpdateMemberListSubscription` command to re-subscribe to new ranges.

## 5 · Testing quirks

- **All tests are inline `#[cfg(test)] mod tests`** in the same file as the code — no `tests/` directory.
- Tests use `ratatui::backend::TestBackend` for render assertions.
- Temporary files in `std::env::temp_dir()` are used in integration-style tests; always clean up.
- **Do NOT add `#[should_panic]` assertions.** Never use `Result::unwrap()` in tests unless inside a `#[test]` that already handles it by returning `Result<()>`.
- Some tests (image preview, media targets) are CPU-intensive due to image decoding; run selectively with `cargo test -- <filter>`.
- `cargo test --all-features` is what CI runs — make sure feature-gated code paths compile.

## 6 · Build / config quirks

### Build profile
`profile.dist` in `Cargo.toml` — `lto = true`, `codegen-units = 1`, `strip = true`.
Only used by `cargo-dist`, locally `--release` uses Rust defaults.

### Windows / printer breaks
- `open_url_command` uses `cmd /C start "" url` on Windows, `open` on macOS, `xdg-open` on Linux.
- No `#[cfg(windows)]` path for file permissions (`chmod 0600` is skipped on non-Unix — silently no-ops on `write_private_file`).

### XDG / config paths (`src/paths.rs`)
```
XDG_CONFIG_HOME/concord/config.toml    — config
XDG_CONFIG_HOME/concord/credential      — Discord token (plaintext; 0600 on unix)
XDG_CONFIG_HOME/concord/concord.log     — log file
dirs::download_dir() / ~/Downloads      — attachment downloads
```
`XDG_CONFIG_HOME` is only respected if it's an absolute path.

### Image protocol detection
`src/tui/media/protocol.rs:query_image_picker` calls
`ratatui_image::picker::Picker::from_query_stdio()` at startup once.
Gracefully degrades through Kitty → iTerm2 → Sixel → Halfblocks.

### Logging (`src/logging.rs`)
- `CONCORD_DEBUG=1` (or `true`/`yes`/`on`) → writes `DEBUG` + `TIMING` lines to log file
- `CONCORD_LOG_FILE=/path` → overrides default log path
- In-app diagnostics popup: press `` ` `` (backtick) — renders the last 200 error entries
- Both `debug()` and `error()` use a `OnceLock` logger that is lazily initialized from environment — writing to the in-memory error store picks up debug lines.

## 7 · Release / changelog workflow

1. `git cliff` (configured via `cliff.toml`) — conventional-commit-based with GitHub PR enrichment; requires `GITHUB_TOKEN` for PR/contributor lookup.
2. `cargo-dist` (v0.31.0, `dist-workspace.toml`) — builds per-platform artifacts; targets: x86_64/aarch64 × apple-darwin/linux-gnu/windows-msvc.
3. Push a tag matching `**[0-9]+.[0-9]+.[0-9]+*` → release workflow builds artifacts, creates GitHub Release, optionally publishes Homebrew formula.
4. After `Release` workflow succeeds → `crates-publish.yml` runs `cargo publish --locked`.
5. `dist-workspace.toml` has `allow-dirty = ["ci"]` so you can manually patch `release.yml` without blocking `cargo dist plan` lint.

## 9 · Unusual parts worth preserving while editing

### Redraw debounce (`runtime.rs`)
Background Discord events are coalesced into an 80 ms debounce (`BACKGROUND_REDRAW_DEBOUNCE`).
Key/mouse/image-decode arms still immediately set `dirty = true` — keep this invariant.

### Version check (`version_check.rs`)
Calls `https://index.crates.io/co/nc/concord` directly (the crates.io sparse index).
Does not use `semver` crate — version parsing/compare is hand-rolled in `ComparableVersion`.
Ignores yanked and pre-release (unless current is also pre-release).

### Image preview budget (`app.rs`)
`MESSAGE_HISTORY_LIMIT = 50`, `MAX_ATTACHMENT_PREVIEW_BYTES = 8 MiB`,
`MAX_ATTACHMENT_DOWNLOAD_BYTES = 64 MiB`, `MAX_CONCURRENT_ATTACHMENT_PREVIEWS = 4`.
These are server-side tool constants.

### Member subscriptions (`runtime.rs:start_command_loop`)
When a user opens a new guild, the code explicitly subscribes via
`SubscribeDirectMessage` + `SubscribeGuildChannel` + `UpdateMemberListSubscription`
to ensure presence events stream even before the user types a message.
On scroll into a new 100-member bucket, `UpdateMemberListSubscription` is re-sent
with the new range, driving continuous member updates on screen.

### Attachment deduplication across cache types
`ImagePreviewCache` keeps viewer and inline entries separate (different `viewer` flag in key).
`AvatarImageCache` / `EmojiImageCache` are independent LRU pools.
Previews, avatars, and emoji image requests flow through different `next_requests` calls.

### Color / accent propagation
The `accent_color: Option<u32>` field on `ImagePreviewRenderInfo` is populated from
`state.message_accent_color()` in `src/tui/message_rows.rs;` it drives the
purple line drawn under the image's message row.

### Media protocols ordered by terminal support
```
Kitty Graphics Protocol → iTerm2 → Sixel → Halfblocks (fallback)
```
Detected on startup via `Picker::from_query_stdio`.
